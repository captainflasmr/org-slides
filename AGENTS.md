# AGENTS.md

## Repo shape
- This is a single-file Emacs Lisp package, not a multi-package app.
- The implementation lives in `org-slides.el`; the regression suite lives in `test/org-slides-test.el`.
- `org-slides.el` declares `Package-Requires: ((emacs "27.1") (org "9.4"))` and requires Org at runtime.
- The package is a GPLv3 fork of `org-present.el` by Ric Lister. Keep the original copyright and license notices in the file header and `README.org`.

## Verification command
- Run the ERT suite:
  - `emacs -Q --batch -L . -l test/org-slides-test.el -f ert-run-tests-batch-and-exit`
- The suite exits nonzero if any test fails; the current pass condition is `0 unexpected`.

## Architecture and workflow
- `org-slides-mode` is the minor mode. Enabling it runs `org-slides--setup`; disabling it runs `org-slides--teardown`.
- `org-slides-start` is the user entry point. It enables the mode and runs `org-slides-after-navigate-functions` for the initial slide.
- Navigation commands narrow to the current top-level subtree unless the one-big-page view is active.
- Tall slides are paged by scrolling one screenful at a time in the same window.  `org-slides--next-page`/`--prev-page` use window start/end positions; page starts are stored as markers.  A page break must never skip unseen text: use the window end directly, moving back only to a word boundary when it lands mid-word.
- At the end of the last slide, `org-slides-next` must stay on the final page and report the end of the presentation.  Do not fall back to `org-slides-top`, which resets the slide to page 0 and creates a back-and-forth loop.
- `org-slides-prev` at page 0 of a slide enters the previous slide at its last page (`org-slides--show-last-page-if-changed`), not page 0.  This makes backward navigation traverse every sub-page in reverse.  If the destination logical start is unchanged (title page or first slide with no previous slide), stay on page 0.
- Incremental list-item reveal: `org-slides--setup-bullets` collects Org `item` elements in the current page, shadows each item's own text (excluding nested items) with `org-slides-bullet-shadow`, and tracks `org-slides--bullet-index`.  `org-slides-step-forward` reveals the next item then advances; `org-slides-step-backward` shadows the previous item then goes back.  Forward page/slide entry starts shadowed; backward entry starts fully revealed on a first visit.  `--clear-pagination` must clear bullet overlays and markers.
- Reveal state is stored in `org-slides--bullet-state`, a hash keyed by `(slide-start . page-index)` for split mode (or `(slide-start . scroll)` for scroll mode).  `org-slides--setup-bullets` restores the saved count and only uses the forward/backward default on a first visit; `org-slides--save-bullet-state` runs after every reveal/hide.  Do not clear this hash on page navigation; only reset it on presentation setup/teardown.
- Shift+Space is not reliably distinguishable from Space on every GUI/terminal input path.  Keep `S-SPC` bound for environments that report it, but also bind `b`, `S-TAB`, `Backspace`, and `C-c C-b` as backward-step alternatives; `f` is the forward-step alias for SPC.  The editing wrappers must preserve their normal behavior in read-write buffers.
- The experimental `org-slides-page-style` `split` computes page ranges while the logical slide is narrowed.  Pages break at buffer line boundaries (so narrowing does not reflow them), prefer nested headings when the preceding page stays at least half full, and are recomputed after window-size/text-scale changes.  `org-slides--show-split-page` narrows to exactly one range; `org-slides--logical-start/end` markers restore the full slide for recomputation.
- Slide numbers count top-level headings in document order (title page = 0).  Page indicators use `SLIDE.PAGE`, live in `mode-line-process`, and are shown on every slide by default (`org-slides-page-indicator` = `always`).  The indicator also includes total slides and total pages via `org-slides-page-indicator-format`.  The mode line does not affect text height, so it is not part of page fitting.  Save and restore the user's original `mode-line-process` in setup/teardown.
- The demo pane is a right-hand side window.  `org-slides--update-demo` runs from `org-slides--enter-slide` before pagination, so split pages are computed with the final window width.  A slide's spec comes from its `DEMO` property, then the first `#+DEMO:` keyword in the slide, then `org-slides-demo-default`.  Literal `#+DEMO:` lines inside blocks are ignored.  `#+DEMO: none` hides the pane.  Use `display-buffer-in-side-window` via `display-buffer` and tag the window with `org-slides-demo` / `org-slides-demo-presentation` parameters; `org-slides--demo-window` finds it by parameter rather than layout.
- Demo resources are buffer-local to the presentation: `org-slides--demo-window`, `--demo-spec`, `--demo-processes`, `--demo-created-buffers`, and `--demo-temp-files`.  `org-slides--demo-reset` runs in setup and teardown, stops demo processes, kills only buffers created by org-slides (command/EWW/xwidget), deletes temporary video pages, and clears demo mode in the demo buffer.  Do not kill file or user buffers.
- `org-slides-demo-mode` in a demo buffer provides `C-c C-o` (return), `C-c C-d` (detach/hide), `C-c C-f`/`C-c C-b` (reveal/shadow bullets, then page/slide), `C-c C-n`/`C-c C-p` (page/slide navigation), and `C-c C-q` (quit).  Navigation from the demo temporarily selects the presentation window and restores the demo window afterward.
- `org-slides-demo-use-window` adopts the selected window as the demo for a manually split layout.  It tags the window with `org-slides-demo`/`org-slides-demo-presentation`/`org-slides-demo-adopted`, enables demo mode in its buffer, and clears any previous demo window.  Adopted windows are never deleted by `org-slides--demo-detach-window`/`org-slides--demo-hide`; the window is untagged and left showing its buffer.  `org-slides--update-demo` keeps an adopted window on slides with no `DEMO` spec when `org-slides-demo-keep-adopted` is non-nil (default t), so demo-mode navigation keys remain available; set it nil to detach on such slides.  `org-slides--demo-display` reuses an adopted window with `set-window-buffer` instead of creating a side window.  The command requires a visible active presentation in another window.
- Video demos use xwidget-webkit when available and a graphical frame is present; local files are wrapped in a temporary HTML page.  Otherwise `org-slides-demo-video-player` (nil/system handler, shell command string, or function) plays the video externally.  Do not make tests depend on xwidgets or network access.
- Demo macros: `macro:NAME` reuses the visible demo buffer (or creates `*org-slides-demo*`), displays it, then plays the macro with the demo window selected.  `DEMO-MACRO` property/keyword runs after the slide's `DEMO` buffer is shown.  Named keyboard macros are kmacro commands, so run them with `call-interactively`; register values and string/vector function definitions go through `execute-kbd-macro`.  `org-slides-demo-macro-delay` schedules playback with a buffer-local timer; cancel it at the start of `org-slides--update-demo`, in `org-slides--demo-hide`, and in `org-slides--demo-reset`.  Macro failures are reported with `message` so a bad macro does not abort slide navigation.
- Timed macros are separate from standard kmacros: entries are `(TIMESTAMP . KEYS)` conses, with timestamps measured from recording start.  Recording uses a global `pre-command-hook` and `this-command-keys`, stores entries newest-first, and finishes with `nreverse`.  The hook ignores the stop/toggle commands and cancels on `C-g`.  Playback is asynchronous: `org-slides--timed-macro-playback-step` runs one chunk per timer callback, computes each target time as `TIMESTAMP * speed` from its own start, and calls `redisplay` after each chunk.  This keeps Emacs responsive and shows intermediate states instead of blocking until the end.  Each chunk selects the demo window only inside `with-selected-window`, so the presentation window is selected again between steps; the presenter can reveal bullets or navigate while the demo plays.  Navigating slides cancels the playback.  The active playback plist is in `org-slides--timed-macro-playback`; cancel it with `org-slides--timed-macro-cancel-playback` from `org-slides--demo-cancel-macro`, slide changes, and teardown.  `org-slides--timed-macro-play-entries` remains the synchronous helper for tests/programmatic use.  `timed-macro:NAME` resolves a variable holding the entries, `last` uses `org-slides-timed-macro-last`, and `DEMO-TIMED-MACRO`/`#+DEMO-TIMED-MACRO:` pairs a timed macro with the slide's demo buffer.  Reuse `org-slides--demo-call-in-window` for playback so demo-mode keys do not shadow recorded keys.  `C-c C-t` toggles recording; document that stopping via `M-x` records the `M-x` invocation.
- Macro definitions can live in named `emacs-lisp` source blocks in the presentation buffer.  `org-slides--named-block-value` widens, finds the block with `org-babel-find-named-block`, requires `emacs-lisp`, and evaluates it with `org-confirm-babel-evaluate` nil, `inhibit-message` t, and forced `(:results . "silent")` so it does not insert results.  Standard macro resolution evaluates a same-named block only when the symbol is not already `fboundp`; timed macro resolution evaluates the block before falling back to a variable, so the block wins.  `org-slides-timed-macro-insert-block` and `org-slides-keyboard-macro-insert-block` generate named `:exports none :results silent` blocks at point.  Do not evaluate other languages as macro definitions.
- `org-slides--add-overlays` hides `#+` keyword/block delimiter lines, heading stars, and emphasis markers, and (when `org-slides-hide-noexport-src` is non-nil) whole source blocks whose parameters contain `:exports none`.  Complete-line and whole-block overlays must include the trailing newline; otherwise they leave blank lines around source blocks.
- Do not hide `#+` lines that are literal content inside source/example/quote blocks.
- The text scale is saved on setup and restored on teardown. Overlay and cursor state is buffer-local.

## When changing code
- If you change navigation, overlay, or scale behavior, update `test/org-slides-test.el`.
- Keep the package self-contained; integrations such as `org-table-fit` belong in the user's config via `org-slides-after-navigate-functions`.
- Preserve the default backward navigation keys: `p`, `S-SPC`, and the left arrow.
